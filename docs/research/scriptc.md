# scriptc feasibility

Reviewed **2026-10-28** against **scriptc v0.4.5**, released 2026-10-25. The question is whether it should compile 1harness's terminal client, long-lived session service, and extension host. This is a documentation/source review; no compiler installation, compatibility smoke test, or benchmark was performed. [Release](https://github.com/vercel-labs/scriptc/releases/tag/v0.4.5)

## Recommendation

**Defer scriptc for the main runtime.** Its fixed module graph and lack of runtime JavaScript execution conflict with loading user-installed TypeScript/JavaScript extensions. Keep the project on its declared TypeScript/Node toolchain. Consider scriptc later for a small helper whose code and dependencies are fixed at build time, after measuring a concrete packaging or startup need.

An external Node extension process or native FFI could bridge particular gaps, but would introduce another runtime boundary. This review does not establish a benefit that justifies that architecture.

## Distribution

The installer requires Node 24+ and selects a native compiler package. Compiler hosts include macOS 15+ arm64/x64, Linux arm64/x64 with glibc 2.34+ or musl, and Windows x64. Outputs include desktop executables, WASI Preview 1, and mobile static libraries. Cross-compilation needs the matching-version runtime pack, target linker/sysroot, and generally Zig; iOS requires macOS. WASI lacks the sockets/processes/signals needed by this service. GNU/Linux outputs can be dynamically linked; musl targets produce static executables. NixOS execution and packaging were not tested. [Installer manifest](https://github.com/vercel-labs/scriptc/blob/v0.4.5/packages/cli/package.json), [platform requirements](https://github.com/vercel-labs/scriptc/blob/v0.4.5/docs/content/docs/platforms.mdx)

## Smallest useful experiment

Keep any experiment outside the production build, in temporary storage with a pinned v0.4.5 compiler and an ephemeral Nix toolchain:

1. Write one dependency-free `smoke.ts` helper: spawn a fixed JSONL fixture child, relay its output through a loopback HTTP stream, then cancel and close both resources.
2. Run the identical inputs under Node as the reference. Compare output, exit status, child cleanup, and HTTP shutdown with the compiled executable.
3. Separately try a minimal computed import of a plugin path created after compilation. Record the diagnostic; do not redesign the extension model to make the experiment pass.

```sh
scriptc coverage smoke.ts --fail-on=divergences --print=diagnostics
scriptc build smoke.ts --optimization=dev -o smoke-native
./smoke-native
```

Review deferred package diagnostics as well as exit status: coverage gates exclude deferred JavaScript operations. Only extend this experiment to the actual TUI/MCP/database dependencies if the helper demonstrates a useful measured benefit. [Coverage semantics](https://github.com/vercel-labs/scriptc/blob/v0.4.5/docs/content/docs/coverage.mdx), [CLI options](https://github.com/vercel-labs/scriptc/blob/v0.4.5/docs/content/docs/cli.mdx)
